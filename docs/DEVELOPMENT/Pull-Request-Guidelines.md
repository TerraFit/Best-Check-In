# Pull Request Guidelines

## Documentation First

PRs that introduce architectural, commercial, or user-facing features must include:

- Feature Registry update  
- Feature documentation update  
- Package impact review  
- Product Decision entry (if applicable)  
- AI documentation update (if architecture / agent rules change)  

Prefer documenting first (or in the same PR ahead of code review focus). Code-only product changes without docs are out of process.

## General

- Describe *why* and *what*.  
- Link Feature Registry IDs / Product Decisions.  
- Screenshots for UI.  
- Note package impact.  
- Do not mix unrelated refactors with feature work.
